# Handoff Work

让下一会话能从已知事实继续，不重新探索整段聊天。

复用用户指定的位置或任务已有交接文件；没有时写入 `.agents/work/<主题>/handoff.md`。用户指定临时目录时遵循该位置。不自动发送消息给其他 agent 或外部人员。

记录有用的最小恢复上下文：

- 目标、已授权范围与明确不做的事项。
- 当前分支或工作目录、已完成与未完成内容；未提交变更及用户原有修改要区分，说明暂存内容的归属。
- 多人任务的当前负责人、接手人（已知时）、依赖任务与集成状态；按需补充工作区和 Git 操作负责人、成果 ref/SHA，集成结论注明实际源成果和目标版本。没有明确分配就写未确定，不擅自安排同事。
- 计划、需求、重要代码和相关决策笔记的链接，不复制已经保存的正文。
- 实际运行的验证与结果；失败、未运行及原因分开写。按任务规模记录关键命令、运行目录及验证时的 HEAD SHA；有未提交内容时附可识别的差异或快照及相关未跟踪文件，不能仅凭 HEAD 和 dirty 标记确定受检内容。说明验证后是否又有相关改动。无 Git 时记录可识别的文件或快照状态，不把“通过”归给尚未验证的后续修改。
- 阻塞问题、未验证假设和下一项可执行动作。
- 可用技能中适合下一步的名称和理由，不引用并未安装的技能。

状态来源于当前文件和工具结果，不仅靠聊天回忆。不写密钥、访问令牌或不必要的个人信息。相对链接以交接文件所在位置为准，保存前检查可达性。

长期原因仍由 [decision-notes](../decision-notes/SKILL.md) 管理，不把交接状态写进决策目录。交接中如引用旧 accepted 决策，接手时仍需重新检索其当前状态。

交付文件路径并指出建议下一步。提醒下一会话先检查工作区与验证现状，交接文件不是当前状态的绝对保证。

交给同事时优先使用项目已有共享位置。文件仅在本机或被忽略时明确说明尚未共享；未获授权不自动推送或发送通知。
