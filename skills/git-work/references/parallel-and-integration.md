# 并行工作区、集成与恢复

独立实现任务需要不同基线、分别提交或存在写入冲突时，优先使用独立 worktree。隔离单位是任务；只读研究、审查或轻量文件分工不要求每个 agent 建一个 worktree。

## 选择工作方式

| 场景 | Git 操作与交付 |
| --- | --- |
| 单 agent 的局部工作 | 可留在当前 checkout，保护已有修改 |
| 多 agent 共享 checkout | 明确修改范围；一个负责人管理 index、提交、切分支及集成 |
| 独立 worktree 并行实施 | 各任务分别有 Git 负责人；交付固定版本，由协调者集成 |

独立 worktree 隔离文件、HEAD 和 index，但通常共享分支、tag、remote 等引用及仓库配置。更改共享引用或配置仍需协调，不通过强行允许同一分支在多个 worktree 中检出来规避隔离。[Git worktree 文档](https://git-scm.com/docs/git-worktree)

## 准备任务与基线

复用已有计划或任务记录，按需要明确负责人、工作目录、允许修改范围、基线版本、前置依赖、共享接口和集成目标。重叠修改先确定由谁交付或怎样集成；未知负责人影响写入时澄清该范围，独立只读调查可继续。

新 worktree 必须来自任务实际需要的版本，不能默认主分支就是正确起点。当前 checkout 的未提交修改不会自动复制过去；任务依赖 dirty 内容时，明确要带入的内容、来源及可恢复方式，或先交付依赖再开始。不能擅自提交或 stash 用户修改来制造基线，也不能在缺少依赖的工作区验证后宣称任务已完成。

共享 checkout 中，worker 默认只编辑分配内容，Git 负责人统一构造提交。在最终检查、验证与提交窗口暂停其他写入；暂停后重新核对状态，结束后说明新的基线。另一个 worker 提前暂存的内容不会因使用不同分支名称而获得独立 index。[Git commit 文档](https://git-scm.com/docs/git-commit)

## 集成与证据

worker 交付实际版本、改动范围、验证命令与对应内容、未解决限制；分支名用于定位，SHA 用于确定版本。协调者按依赖顺序选择项目要求的 merge、rebase 或 cherry-pick，不由技能默认改变历史策略。

自动集成或跨任务组合至少固定并核对三个对象：

- **source**：实际待集成的源 commit。
- **target**：构造候选结果时的目标 commit。
- **candidate**：两者集成后的实际内容或 commit。

源分支测试和评审只覆盖其实际检查对象；在 candidate 上完成组合所需检查后才报告集成通过。`approved`、任务完成标记或分支名不能代替证据。源、目标或冲突解决内容发生变化时重新构造候选结果，更新受影响检查；同一 tree 也需确认验证环境、依赖和检查输入未变才能复用证据。重试或提交前重新核对引用，避免把检查过的版本换成刚移动的分支。

验证记录只是证据，不得为了保存状态或日志自动暂存、提交任务代码；工具的内部 commit 同样受授权和 index 归属规则约束。

## 冲突与恢复

先确认冲突属于哪个 merge / rebase / cherry-pick、双方意图及目标行为，保留各自必要修改，再按内容解决并执行受影响检查。不能默认整批选择 ours / theirs，也不能把冲突标记消失当作行为正确。

已有授权涵盖合理冲突处理时继续完成，不为每个文件重复询问。无法从需求和代码判断的重要冲突需要澄清；其他独立工作可继续。是否 continue、abort 或改用另一集成方式取决于任务意图和当前状态，没有“永不 abort”的要求。

恢复到已知状态前核对哪些修改属于本次操作、哪些是之后产生的外来工作；不要用 reset / clean 抹掉未知内容。共享已发布历史通常用追加修复或 revert，重写需有对应授权与项目约定。revert 代码不能自动撤销部署、迁移或外部系统副作用，恢复范围必须据实说明。

授权重写远端历史时，`--force-with-lease` 仍需核对目标引用及已审阅的远端预期 SHA；只依赖本地 remote-tracking 引用会受到后台 fetch 的影响。使用明确的预期版本，并在远端变化后重新判断，不以失败为由改成无条件 force。[Git push 文档](https://git-scm.com/docs/git-push)

删除 worktree 或任务分支前，区分代码是否已集成、引用是否持久保留、文件是否仍待交付。detached HEAD 的提交先保存为可恢复引用或经确认的归档；忽略文件中仍需保留的成果另行保存。目录 clean 只说明没有 Git 当前报告的待提交变化。
