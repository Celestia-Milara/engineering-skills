# 多人协作与范围变化

多人接手同一任务、共享 checkout、跨任务依赖，或实施中改变需求维护来源时，按相关章节处理；单人小改无需读取团队流程。

## 开始与协作

核对本次负责的切片、实际基线、前置依赖及重叠修改。不要覆盖同事工作或把未集成依赖当成已完成；共享接口需要变化时标明受影响任务和兼容顺序。负责人未知且影响写入范围时先澄清该范围，其余只读调查可继续。

共享 checkout 的 Git 操作者、稳定验证窗口及独立 worktree 的选择，遵循 [Git 底线的并行与集成章节](git-safety.md#并行与集成)。需要具体工作区、集成或恢复操作且已安装时可用 git-work，未安装时按上述底线直接完成必要检查。

## 范围变化

若用户在实施中调整范围或验收，按已有写入授权同步需求维护来源，再更新受影响的计划条目；暂未同步的来源注明差异。只有聊天要求时无需为此新建文档，不能让旧要求继续冒充最新要求。

## 团队交付

说明基线或分支、实际成果版本、共享接口及迁移影响、依赖是否已经集成。验证身份和集成证据遵循 [Git 底线](git-safety.md#验证对象)；局部检查只代表其范围，在实际候选组合上检查后再报告集成通过。
