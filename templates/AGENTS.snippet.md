## Git 底线

- 修改前确认仓库、工作目录、分支或 detached HEAD、基线、已有变化和完整暂存内容；检查 `git status`、工作区差异与 `git diff --cached`，辨认本任务范围。工作区不干净不自动中止任务。
- 每个 worktree 只有一个 Git 操作负责人。共享目录的子 agent 按分工编辑，由协调者负责暂存、提交、切分支与集成；最终验证、暂存和提交期间协调暂停其他写入。独立任务需要分别提交、不同基线或可能冲突时按需使用独立 worktree，并确认正确起点。
- 保留原有修改及暂存状态，不为清理目录自动 stash、清空暂存区、reset 或删除文件。已有 staged changes 不自动属于本任务；需要调整时遵循已有授权。
- 提交只包含归属明确的任务变化，审查完整待提交差异，按逻辑变化组织提交。明确路径暂存仍可能夹带同一文件内的他人修改，不能用路径代替归属检查。
- 默认不自动 commit；任务或项目明确允许后执行，不重复请求已有授权。push、远端合并和共享历史重写沿用各自明确授权，本地提交授权不自动包含它们。提交格式和 AI trailer 服从项目政策。
- 验证对应实际检查的内容。工作区与暂存内容不同时不自动复用验证；存在未提交修改时不能只用 HEAD SHA 标识验证版本。内容或集成结果变化后重新判断受影响检查，纯消息变化且内容未变时可复用内容验证。
- 集成前确认源版本、目标版本及交付证据，集成后验证实际组合；各分支分别通过不代表组合通过，分支名或 `approved` 状态不能代替版本身份。
- 清理 worktree 或分支前确认成果已集成或有可恢复引用，detached HEAD 的提交先保存引用。工作区 clean 不代表成果已经推送或集成。
