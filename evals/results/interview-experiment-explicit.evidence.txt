Note Format\n\n文件名 `YYYY-MM-DD-<status>-short-topic.md`。日期是首次创建日，查实际日期，不要凭印象；状态词取 `proposed` / `accepted` / `rejected` / `superseded` 之一，必须与头部 `Status` 完全一致（D022）——目录列表因此能直接读出每篇笔记的生命周期，两者不一致时以修正文件名为准；主题用小写英文 kebab-case，描述决策主题而不是任务本身。\n\n**状态变化就是一次重命名**：改完文件名，必须修掉所有指向旧文件名的地方——`Superseded-By`、正文相对链接、代码里的 `Decision:` 反向指针；漏改由 D090 / D101 / D110 报出。\n\n```markdown\n# Decision: <标题>\n\nStatus: accepted\nApplies-To: src/worker/**, src/ipc/protocol.ts\n\n## Context\n\n为什么需要做这个决定：问题、约束、触发条件。\n\n## Decision\n\n现行方案是什么，边界在哪。\n\n## Alternatives\n\n- **方案 A** — 为什么看起来合理（对手最强的论据）；为什么最终没有采用。\n- **不做 / 复用现有方案** — 为什么不够。\n\n## Consequences\n\n- Positive: 具体收益。\n- Negative: 具体代价、上限，以及什么情况下应该重新评估。\n```\n\n头部字段：\n\n- `Status`：必填，取值同上。\n- `Applies-To`：除 superseded 外必填。逗号分隔的路径或 glob（相对仓库根），全局约束写 `project-wide`。它是别的 Agent 按路径找到这篇笔记的主要入口，写宽了没用、写错了会失效，改文件名或移目录时一并更新。`rejected` 也要写：填该方案若被重新提出会落在哪些路径，仓库级选型写 `project-wide`，不要为凑字段编造不存在的路径。\n- `Superseded-By`：只在 superseded 时出现，值是同目录下的文件名。\n\n四个二级标题 `Context`、`Decision`、`Alternatives`、`Consequences` 固定，顺序固定，不加别的二级标题。\n\n各状态的含义：\n\n- **proposed**：方案已形成，尚未定案或生效；已授权但尚未实施的目标也使用此状态。只有所需取舍未获授权、存在未解决的分歧或必须由用户决定时才询问，待实施不等于待审批。\n- **accepted**：在笔记声明范围内已经实际生效的决策。用户已明确拍板、授权相关技术选择或委托选型时继续实施；生效时直接写 accepted，不必补走审批。一个任务内已完成的选择无需为形式先创建 proposed。\n- **rejected**：明确讨论过并否决，且未来仍有参考价值。`Decision` 写被否决的方案，`Alternatives` 写最后采用了什么（通常是维持现状），`Consequences` 写不做的代价。\n- **superseded**：曾经有效，已被新决策完全取代。\n\n## 5. Writing Rules\n\n**accepted 用现在时陈述事实**：写「Worker 通过 Message Bus 通信」，不写「将会」「计划」「应该」。读者是半年后只看当前代码的人，笔记跟着代码走。\n\n**不写过程叙事**：「经讨论」「本次修改了」「后续 PR 将」「用户要求」都不要出现，这些是会话残留。\n\n**Alternatives 只写真正考虑过的方案**，不要为凑模板编造。每项写清它为什么在当前约束下合理、为什么没有采用；「不做 / 复用现有方案」只在确实评估过时才写。确实没有任何备选时才可以写：\n\n```markdown\n## Alternatives\n\nNone — 遵循 [某篇已有约束笔记](./2026-08-01-accepted-example.md)。\n```\n\n`None` 必须链接到一篇已有笔记，防止它成为偷懒的默认选项。\n\n**Consequences 必须同时有 Positive 和 Negative**，写成 `- Positive: ...` / `- Negative: ...`。只记真实、具体的内容；Negative 尽量具体到成本、上限或重新评估的条件，识别不出具体代价就重新检查约束和备选，不要编一个来填模板。\n\n篇幅通常 20–60 行，超过 100 行多半是把过程写进去了。\n\n## 6. Back-Pointers in Code\n\n只在「读代码的人会觉得别扭、想简化，但其实是有意为之」的入口处，用项目语言的注释语法加一行：\n\n```ts\n// Decision: 2026-09-21-accepted-worker-runtime-boundary.md — Worker 不直接依赖 Main Process\n```\n\n一处入口一行就够，不要到处撒。\n\n## 7.
